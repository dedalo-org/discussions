# discussions

Where the [`dedalo-org`](https://github.com/dedalo-org) organisation talks.

There is no code here. GitHub attaches Discussions to a repository, and
putting them in `dedalo` would have tied a conversation about the
organisation — a plugin, a design question, a release — to one project's
issue tracker.

**→ [Open a discussion](https://github.com/orgs/dedalo-org/discussions)**

## Which category

| Category | For |
| --- | --- |
| **Q&A** | "how do I…", "why did my round…". Answerable, so a thread closes with an answer someone else can find. |
| **Ideas** | A change you want, before it is an issue. Cheaper to reject a paragraph than a branch. |
| **Show and tell** | A project using Dedalo, a round you ran, something you built on top. |
| **Announcements** | Releases and decisions. Maintainers post; anyone replies. |
| **General** | Everything else. |

## What does not go here

**Security issues.** Never in a public thread — not a suspected one, not a
"probably nothing". A wrong amount, a leaked key, credit assigned to the wrong
person: all of it goes through a
[private advisory](https://github.com/dedalo-org/dedalo/security/advisories/new).
See [SECURITY.md](https://github.com/dedalo-org/.github/blob/main/SECURITY.md).

**Bugs with a reproduction.** Those are issues, on the repository they affect —
[dedalo](https://github.com/dedalo-org/dedalo/issues),
[dedalo-nvim](https://github.com/dedalo-org/dedalo-nvim/issues). A discussion
is for when you are not yet sure it is a bug.

**Private keys, seed phrases, or anything from a wallet.** Nobody here will
ever ask for one, and a revoked key is still a key someone can learn from.
Addresses are public and fine to paste; the thing that signs for them is not.
